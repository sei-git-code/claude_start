# サンドボックス反映手順

このカタログを別マシン・コンテナ・VM等の「サンドボックス環境」に持ち込んで再現するための手順。対話操作できる環境（開発者がその場にいる）と、対話操作できない環境（CI・自動起動コンテナ等）で手順が分かれる。

## 前提

- git
- bash（Windowsの場合はGit Bash）
- Claude Code CLI（`claude`コマンド）
- `jq`（ステータスライン・hookスクリプトが依存。未導入なら `../jq/install-jq.sh` で自動インストール）
- 選ぶモジュールによっては追加で Node.js（`../nodejs/`、Context7 MCP用）、`gh` CLI（`/commit-push-pr`用）が必要

## A. 対話操作できるサンドボックス（推奨）

1. リポジトリをサンドボックスにクローンする。
   ```bash
   git clone https://github.com/sei-git-code/claude_start.git
   cd claude_start
   ```
2. `jq` が無ければ入れる。
   ```bash
   bash modules/jq/install-jq.sh
   ```
3. クローンしたディレクトリで `claude` を起動する（既存プロジェクトから読み込む場合は `claude --add-dir` でこのディレクトリを追加）。
4. Claude が `CLAUDE.md` のカタログを提示し、項目ごとに導入可否を確認してくる。1つずつ回答する（一括自動導入はされない仕様）。
5. 導入後、Claude が動作確認まで行ったことを確認してから完了とする。

これが基本の手順。README.md の「使い方」と同じ流れをサンドボックス側でもそのままなぞればよい。

## B. 対話操作できないサンドボックス（CI・自動起動コンテナ等）

TTYが取れない環境では、`security-guardrails` の「不可逆操作の確認y/Nゲート」フックは確認なしで通過しログにのみ記録する仕様（`modules/security-guardrails/README.md` 参照）。同様に、Claude が `AskUserQuestion` でカタログ項目を1つずつ尋ねても応答者がいなければ処理が止まる。

この場合は事前に全項目の可否を書面で決めておき、`INITIAL_PROMPT.md` のテンプレートに埋めてからセッション開始プロンプトとして渡す。これにより「1項目ずつ確認する」というCLAUDE.mdの要件は、対話の代わりに事前合意済みの回答書で満たされる（Claudeが追加で聞き返す必要がなくなる）。

手順:
1. 上記A.の1〜2（クローン・jq導入）をサンドボックス構築スクリプトに組み込む。
2. `INITIAL_PROMPT.md` をコピーし、各項目に yes/no を埋める。
3. 埋めたテキストを、サンドボックスで起動する `claude` セッションの最初のメッセージとして渡す。
4. Claude は事前回答に従って項目を適用し、可能な範囲で動作確認してから完了報告する。

## 注意

- `gh auth login` のような対話ログインが前提のモジュール（`/commit-push-pr`）は、非対話サンドボックスでは事前に別途トークン発行等で認証を済ませておく必要がある。CLAUDE.md記載の通り、素のターミナルで行い、Claude Code経由の疑似端末は使わない。
- `.env` や認証情報をサンドボックスにコピーする場合も、ユーザーのグローバルCLAUDE.md（機密情報の取り扱い）の制約は変わらない。値を直書きせず環境変数参照にする。
- Unity MCP はUnity Editor本体のインストールと接続設定が別途必要なため、サンドボックスへの自動反映対象には基本含めない。
