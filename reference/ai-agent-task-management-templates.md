# AIエージェント運用テンプレート集（未導入・参考情報）

出典: [複数のAIコーディングエージェントを実務で運用するためのワークフロー設計](https://qiita.com/Y-Y-dev/items/d526fb7cdbe35a3f9384)

Claude Code固有の設定ではなく、AIコーディングエージェント（Claude Code / ChatGPT等）を業務で使う際の運用フレームワークを紹介した記事。具体的なコマンドやインストール手順はなく、テンプレートと役割分担の考え方が中心。

## 記事の要点

### 1. CLAUDE.mdの運用ルール例
リポジトリ直下に置く指示ファイルに、テスト実行方法・禁止事項・Git運用ルール・完了条件の報告形式を明記する例。

```markdown
# Claude Code運用ルール

## テスト実行方法
- npm test
- pytest tests/

## 禁止事項
- 公開済みデータの変更
- APIレスポンス形式の変更
- 無関係なリファクタリング

## Git運用
- コミットにはタスクIDを含める
- ブランチは feature/[TASK-ID] 形式

## 完了条件の報告形式
- 変更ファイル一覧
- テスト件数と結果
- 実施できなかった検証項目の明記
```

### 2. task-list.md（進捗管理の唯一の正本）
`docs/task-list.md` に置く進捗管理テーブル。ID・タスク名・状態・進捗率・依存関係・完了条件・証拠の7項目を必須とする。

```markdown
| ID | タスク | 状態 | 進捗 | 依存 | 完了条件 | 証拠 |
|---|---|---|---:|---|---|---|
| DEV-001 | APIの作成 | 完了 | 100% | - | テスト成功 | PR #12 |
| DEV-002 | 機能実装 | 進行中 | 70% | DEV-001 | 条件満たす | - |
```

### 3. タスク指示テンプレート
AIへの指示を「対象タスク／開始前確認／目的／変更範囲／完了条件／テスト方法」の構成で渡す型。完了条件はYes/Noで判定できる形にすることを推奨している。

```
# 対象タスク
[TASK-ID] タスク名

## 開始前確認
- Git状態確認コマンド: git status, git log --oneline -1

## 目的
[ビジネス背景を含めた説明]

## 変更範囲
- 対象ファイル明記
- 禁止ファイル明記

## 完了条件
[Yes/Noで判定可能な形式]

## テスト方法
- Unit Test: [コマンド例]
- Integration Test: [コマンド例]
```

### 4. 複数AI運用時の役割分担
ChatGPT（要件整理・指示作成・レビュー）とClaude Code（コード調査・実装・テスト）で役割を分け、受け渡す情報はタスクID・変更対象・完了条件・差分のみに絞る（リポジトリ全体を都度渡さない）という考え方。

### 5. 実装運用フロー
仕様確認 → 実装 → テスト追加・実行 → 差分レビュー → ドキュメント更新 → コミット（`feature/[TASK-ID]`形式）→ Draft PR作成 → 完了報告、という一連の単位で作業する。

## なぜ「参考情報」止まりか
具体的なコマンドやツール設定を伴わない、運用方針・テンプレートの提示が中心の記事のため、他のmodules/項目のように「導入手順」として配布できるものではない。実際に採用するかはプロジェクトの規模・体制次第で判断が変わるため、必要になったタイミングでこのファイルを参照し、該当プロジェクトのCLAUDE.md・task-list.md等に個別にカスタマイズして反映するのが向いている。
